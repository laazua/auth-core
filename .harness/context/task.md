## 业务背景

角色管理页是 RBAC 核心页面，提供角色全生命周期管理与权限分配。权限分配采用树形结构，按模块分组展示权限，支持勾选/取消勾选、父子节点联动、展开/折叠、搜索过滤。复用 roles/001-002 后端 API。

## 需求描述

实现角色管理完整页面：

1. **角色列表页** (`/roles`)：
   - 顶部工具栏：搜索框（角色名/编码）、状态筛选、新增按钮
   - 数据表格：角色名、编码、状态、创建时间、操作列
   - 分页器、搜索/筛选、Loading、空状态

2. **新增/编辑角色抽屉/弹窗**：
   - 表单：角色名、编码、状态
   - 表单验证：角色名/编码唯一、编码格式规范（如 ROLE_*）

3. **操作列功能**：
   - 编辑：打开编辑抽屉，回填数据
   - 启停用：切换状态
   - 删除：确认弹窗 → 删除（引用保护：sys_user_role/sys_role_permission 存在则拒绝）
   - 权限分配：打开权限分配弹窗（核心功能）

4. **权限分配弹窗（核心）**：
   - 左侧：权限树（按模块分组、ElTree、勾选框、父子联动、展开/折叠、搜索过滤、展开/折叠全部）
   - 已分配权限高亮显示
   - 保存 → 调用 PUT /roles/{id}/permissions

## 验收标准（TDD 驱动）

### AC1 — 角色列表分页查询与条件筛选
> 访问 `/roles`，默认加载第一页，支持角色名/编码模糊搜索、状态筛选，分页切换正常。

**用例**：`IndexView.spec.ts#queryPaginationAndFilters`
- 搜索关键词 → 列表筛选正确
- 状态筛选 → 列表筛选正确
- 翻页 → 页码、每页条数切换正常

### AC2 — 创建角色唯一校验
> 点击新增 → 填写表单 → 提交 → 返回 200、列表刷新、新角色出现，重复 name/code 返回 409 code=1101/1102。

**用例**：`IndexView.spec.ts#createRoleUniqueNameAndCode`
- 填写有效表单 → 提交成功、列表刷新
- 重复 name → 提示“角色名已存在” code=1101
- 重复 code → 提示“角色编码已存在” code=1102

### AC3 — 更新角色 code 不可改
> 点击编辑 → 打开抽屉回填数据 → 修改 name/status → 提交 → code 不变。

**用例**：`IndexView.spec.ts#updateRoleCodeImmutable`
- 修改 name/status → 保存成功、列表更新
- code 输入框禁用

### AC4 — 启停用、删除引用保护
> 启停用切换生效、删除引用保护（sys_user_role/sys_role_permission 存在则拒绝，code=1103/1104）。

**用例**：`IndexView.spec.ts#statusToggleDeleteReferenceProtection`
- 点击启用/停用 → 状态切换、后端同步
- 分配了用户的角色删除 → 409 code=1103
- 分配了权限的角色删除 → 409 code=1104

### AC5 — 权限分配树功能完整
> 打开权限分配弹窗 → 显示权限树（按模块分组、父子联动、展开/折叠、搜索） → 勾选权限 → 保存 → 后端保存成功、重新打开弹窗勾选状态正确。

**用例**：`IndexView.spec.ts#permissionAssignTreeFunctionality`
- 打开弹窗 → 权限树按模块分组渲染、父子节点联动勾选
- 搜索关键词 → 树过滤高亮匹配项
- 勾选父节点 → 子节点自动全选、取消父节点 → 子节点全取消
- 勾选子节点 → 父节点半选状态
- 勾选权限 → 保存 → 重新打开弹窗勾选状态与保存一致
