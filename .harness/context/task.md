## 业务背景

用户管理页是系统核心业务页面，提供用户全生命周期管理：分页查询、条件筛选、创建用户、编辑用户、启停用、重置密码、角色分配。复用 users/001-003 后端 API，体现 RBAC 权限控制（仅管理员可见）。

## 需求描述

实现用户管理完整页面：

1. **用户列表页** (`/users`)：
   - 顶部工具栏：搜索框（用户名/昵称/邮箱/手机号）、状态筛选、新增按钮
   - 数据表格：用户名、昵称、邮箱、手机号、状态（启用/停用标签）、角色标签、创建时间、操作列
   - 分页器：页码、每页条数、总数
   - 空状态、加载骨架屏

2. **新增/编辑用户抽屉/弹窗**：
   - 表单：用户名、密码（新增必填）、确认密码、昵称、邮箱、手机号、状态
   - 表单验证：用户名唯一、密码长度≥6、邮箱格式、手机号格式
   - 新增时密码必填，编辑时密码可选（不修改则留空）

3. **操作列功能**：
   - 编辑：打开编辑抽屉，回填数据
   - 启停用：切换状态（调用 PATCH /users/{id}/status）
   - 重置密码：确认弹窗 → 调用 POST /users/{id}/password/reset（仅管理员）
   - 角色分配：打开角色分配弹窗（复用 users/002 API）

3. **角色分配弹窗**：
   - 左侧：可用角色列表（复选框、搜索过滤）
   - 右侧：已分配角色列表
   - 双向移动按钮（<< >>）、全选/反选
   - 保存 → 调用 PUT /users/{id}/roles

## 验收标准（TDD 驱动）

### AC1 — 用户列表分页查询与条件筛选
> 访问 `/users`，默认加载第一页，支持用户名/昵称/邮箱/手机号模糊搜索、状态筛选，分页切换正常。

**用例**：`IndexView.spec.ts#queryPaginationAndFilters`
- 搜索关键词 → 列表筛选正确
- 状态筛选 → 列表筛选正确
- 翻页 → 页码、每页条数切换正常

### AC2 — 新增用户密码加密且唯一
> 点击新增 → 填写表单 → 提交 → 返回 200、列表刷新、新用户出现、密码已 BCrypt 加密存储，重复用户名提示“用户名已存在”。

**用例**：`IndexView.spec.ts#createUserEncryptsPasswordAndUnique`
- 填写有效表单 → 提交成功、列表刷新
- 重复用户名 → 提示“用户名已存在”

### AC3 — 编辑用户不含密码、用户名不可改
> 点击编辑 → 打开抽屉回填数据 → 修改昵称/邮箱/手机号/状态 → 提交 → 用户名/密码不变。

**用例**：`IndexView.spec.ts#updateUserExcludesPasswordAndUsername`
- 修改昵称/邮箱 → 保存成功、列表更新
- 用户名/密码输入框禁用/隐藏

### AC4 — 启停用、重置密码、角色分配
> 启停用切换生效、重置密码（管理员）生效、角色分配弹窗双向移动保存生效。

**用例**：`IndexView.spec.ts#statusToggleResetPasswordRoleAssign`
- 点击启用/停用 → 状态切换、后端同步
- 点击重置密码 → 确认弹窗 → 重置成功、可用新密码登录
- 点击角色分配 → 双向移动角色 → 保存 → 角色更新
